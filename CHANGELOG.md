# Changelog

All notable changes to zut. Format: `Added / Changed / Fixed` under `Unreleased`,
moved to a version section on release.

## [Unreleased]

### Changed (2026-10-22 — the mark, everywhere)
- The hand-drawn Zut mark replaces the red "Z" placeholder: title bar, auth
  page, account gate, agent-home step, landing nav and footer, favicon and
  PWA icons (white mark on the dark tile, 192 + 512, generated by
  `scripts/make-icons.py` from the source PNG — the old "~C" placeholder
  icon is gone).

### Changed (2026-10-22 — an account is the door)
- The IDE at /app opens with an account. The gate card asks you to create one;
  creating is free, editing stays free, and local development (localhost) still
  walks straight in.
- Creating an account is a real signup now: email + password, against Supabase
  Auth (or a configured Mudbase project). Signing in works with the password;
  the magic-link path stays as a link under the button.
- First thing after signing in, you pick where the agent runs: on your machine
  (self-host with opencode or a `zut host` — available today) or on Zut Compute
  (our hosted agent — coming online with the server). The choice is remembered
  and switchable later.
- The landing page sells the actual product now: Cursor writes your files and
  then `npm install` runs on your laptop; Zut runs the heavy part on Zut
  Compute. Phone, Chromebook or a 4GB laptop is enough. The waitlist is gone —
  the hero and the final CTA create accounts, and a signed-up user lands in
  the IDE already signed in.
- The built-in Supabase project constants now back the app itself (env still
  wins), so a deployed IDE can see the session the landing page stored.

### Removed (2026-10-22 — the waitlist, retired)
- `WaitlistGate`, `useWaitlistGate`, `lib/waitlist` and the landing waitlist
  capture are gone. The `waitlist` table and its welcome-mail trigger
  (`supabase/waitlist.sql`) can remain in the project; nothing writes to it.

### Changed (2026-10-21 — one row of chrome)
- The diff pane lost its own header. The right pane's header row now carries
  everything: the switcher, the diff summary (`3 files +12 -4`), copy-diff,
  Create PR and Save & deploy — and an overflow menu for the rest. The pane
  is two rows of chrome at most: this one, and the open files.
- The branch selector, the expand button and the second "files uncommitted"
  bar are gone; the actions that were behind the overflow menu are in the
  menu now, and nothing is hidden behind a hover.
- Icons that only repeated their label are gone: the sidebar rows are plain
  text, the editor toolbar buttons are text, and the agent/plan switch shows
  which one you are in.

### Added (2026-10-21 — AI completion)
- The editor offers the rest of the line as ghost text; Tab takes it. It
  talks straight to the provider you already have a key for (OpenRouter,
  Anthropic or OpenAI), so nothing is proxied through us. The *AI* button in
  the editor toolbar turns it off.

### Changed (2026-10-21 — a real window title bar)
- The floating pill above the window is gone. The app now has a title bar
  inside the window, like the reference: the Zut mark and name on the left,
  the project name in the middle, the actions on the right. The wallpaper
  still shows around the window.

### Added (2026-10-21 — documents, questions, build)
- Markdown can be read as a document: a `Document | Source` toggle in the
  file tabs renders the plan as prose (headings, lists, code, quotes) with
  no dependency and no HTML injection.
- The agent can ask instead of guessing. End its reply with a questions
  block and the IDE shows a card: the question, the options, Skip and
  Continue. Your answer goes back as the next turn.
- A `Build` button in the pane header rebuilds the preview and opens it.

### Fixed (2026-10-21 — slow local models)
- A local agent turn timed out after two minutes, which read as a failure
  while the model was still working. Five minutes now, and the questions
  block is stripped from the prose (it is a card, not text).

### Added (2026-10-21 — file tabs, plan mode, task lists)
- The right pane has file tabs: the files you have open, newest last, each
  one clickable (it opens in the editor) and closable.
- The composer has a mode: **Agent** changes the code, **Plan** plans first.
  In plan mode the agent is told to reply with a checklist and to keep its
  hands off the files; the IDE saves the checklist as `PLAN.md` and opens it.
- A plan document is a task list: every `- [ ]` line is a task you can tick
  (the file is rewritten, so the plan and the list never disagree), and
  "Add a task, ⌘K to generate…" appends one.

### Changed (2026-10-21 — the shell, rebuilt to the reference UI)
- The right pane owns its tabs: a quiet strip (Review / Code / Preview /
  Checks) sits at the top of the pane instead of pills floating in the app
  bar. The duplicate switcher inside the diff pane is gone.
- The preview pane grew a real URL bar — back, forward, reload and an
  address field — like the reference browser chrome.
- The composer is one input again: "Plan, search, build anything…". The
  model dropdown lists the local agent's models directly (free first), and
  the separate model select, the free-text model row and the Review /
  Save row are gone — review lives in the file cards and in the pane.

### Removed (2026-10-21 — no defaults)
- The agent's empty state no longer offers pre-baked prompts ("Build a
  landing page", "Create a starter index.html", "Review the workspace and
  suggest next steps"). You open a folder or start from scratch, then say
  what you want.

### Changed (2026-10-21 — the local agent is the default)
- When the local opencode server is up, it is the default model — it is the
  one that works without an API key. A model you pick yourself is never
  overridden.

### Fixed (2026-10-21 — the agent reviews *your* project)
- The agent's workspace is now an exact mirror of the project the IDE has
  open: anything left over from a previous project is removed before the
  turn. Before, a review covered the old files too (and the IDE pulled
  them back as if the agent had created them).
- The agent's scratch workspace (`~/.zut-projects/agent`) and the host's
  real workspace (`~/.zut-projects/host`) are separate directories, so the
  agent can never write into the files you opened.

### Added (2026-10-21 — the local stack)
- The IDE runs on your laptop with no VPS: `npm run dev` starts opencode
  serve, the file bridge, zut-host, the broker and the dev server itself.
  `npm run term:local` puts the same IDE (same agent, same workspace) in a
  terminal window. `npm run local:status` / `local:down` / `local:logs`
  manage the stack. Everything binds loopback; the workspace is
  `~/.zut-projects/default`.
- The dev/preview server starts the stack for you (`scripts/local-stack.mjs`
  via a Vite plugin). `ZUT_LOCAL_STACK=0` opts out; CI never starts it.
- `npm run local:install` installs the stack as a systemd **user** service
  (no root): the IDE and the local agent are up at every login, a service
  that dies is restarted in 2s, and `npm run local:down` stops the service
  instead of fighting it.

### Fixed (2026-10-21 — the local agent)
- The terminal client now checks two things before it hands the screen to
  pixel: that the IDE is actually serving the URL, and that the terminal
  answers the kitty graphics query. A wrong URL or a terminal that cannot
  draw the protocol used to show a broken picture with no explanation —
  now both print what is wrong and what to do.
- The model picker read a flat `/provider` list, but the opencode server
  nests models under their provider — the picker came up empty. Both shapes
  are read now, and an empty list is not cached.
- The IDE decided once whether the local agent was reachable. It now polls,
  so "opencode (self-host)" appears as soon as the server is up.
- The dev server bound `localhost` (IPv6 only); the terminal client and the
  local stack talk to `127.0.0.1`, so it is bound explicitly now.
- The terminal client served a stale `dist/` when sources were newer. It
  rebuilds when the build is out of date.

### Added (2026-10-20 — the IDE in the terminal)
- `zut-term`: the Zut IDE runs inside a terminal window, painting real pixels
  over the kitty graphics protocol with
  [`@zenbu-labs/pixel`](https://pixelgui.com).
  The IDE itself is a WebView, so every pane, modal and editor is the real
  app. New `terminal/` package (own install, so the root stays light) plus
  `npm run term`, `npm run term:setup`, `npm run term:build`. The launcher
  serves the production build (rebuilding when `dist/` is missing), can reuse
  a server that is already up, and offers `--dev`, `--url`, `--port`,
  `--rebuild`.

### Changed / Fixed (2026-10-20 — one theme, one control language)
- `dark:` Tailwind utilities now follow the in-app theme toggle instead of
  `prefers-color-scheme`. Previously 184 utilities across 22 components
  disagreed with the `isDark` ternaries, so an OS-dark machine with the app
  in light mode rendered a half-and-half UI.
- Buttons no longer carry borders. Pills and buttons use a filled surface
  (light `bg-[#f4f4f6]`, dark `bg-[#24242a]`) instead of a border over a
  background — one secondary-button recipe everywhere.
- Solid primary buttons dropped the redundant same-colour border, which was
  invisible but shifted the box by 2px.
- One focus treatment everywhere: `focus:ring-1 focus:ring-red-500`.
- Tab underlines use one red in both themes instead of two.
- Off-system accents removed: the landing orange in the waitlist gate, the
  green language badge in the editor, the green "no checks recorded yet"
  empty state, and the green glow on agent replies. A merged pull request
  reads as success (green) rather than error (red).
- Border colours consolidated onto the `DESIGN.md` tokens; the last
  near-duplicate hexes are gone.
- `DESIGN.md` gained a Controls section (primary / secondary / focus / borders
  / status surfaces) and the theme-mechanism note.

### Changed / Fixed (2026-10-20 — workspace safety)
- Host workspace reloads external edits (3s stamp poll) without clobbering
  pending local writes; local folder reloads snapshot first.
- `git commit` in the host now stages only visible paths (`git add -A --`), so
  `.env*`, `node_modules`, build output, and binaries can never be committed;
  deletions of visible files still stage correctly.
- Lockfiles now sync to host workspaces; `.env*` remains excluded from local
  host sync, repo import, and AI context.
- Fixed debug session ownership: a failed `start()` no longer wedges the host,
  and closing one debug socket cannot stop another viewer's session.
- Host `/health` hides the absolute workspace path unless the request is
  authorized; remote hosts now explain `CORS_ORIGIN` errors.
- GitHub repo import resolves `/tree/<ref>/<path>` URLs (tries long refs first,
  then folder prefixes) and skips secrets.
- Host URLs typed in the connect dialog are normalized before testing/saving.
